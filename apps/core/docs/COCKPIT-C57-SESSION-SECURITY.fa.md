# C57 — بازبینی امنیت نشست و پاسخ‌های معوق

- تاریخ: 2026-10-12؛ فقط Core آزمایشی.
- نشست با `expires_at` پس از لحظه اعتبار، هنگام درخواست توکن مجدداً کنترل و فوراً نامعتبر می‌شود؛ هیچ توکنی به درخواست جدید تحویل نمی‌شود.
- رویدادهای ناشناخته SDK امکان ارتقای نشست ندارند؛ ورود ناموفق مانع callback مثبت دیررس می‌شود.
- پاسخ موفق ۲۰۰ از BFF نیز پس از logout یا چرخش توکن به درخواست‌کننده تحویل نمی‌شود. 401 مربوط به توکن قدیمی، نشست جدید را لغو نمی‌کند.
- خطاهای داخلی، توکن و پاسخ محرمانه در خطای عمومی نمایش داده نمی‌شوند.
- این guard صرفاً سمت کلاینت است؛ کنترل JWT، RLS و حق دسترسی در سرور با این کار تأیید یا جایگزین نمی‌شود.
- داده کاملاً ساختگی؛ هیچ اتصال Supabase/BFF/Production واقعی و هیچ Fetch/Merge/Push/Deploy انجام نشده است.
