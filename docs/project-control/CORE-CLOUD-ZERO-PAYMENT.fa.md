## دامنه
- شاخه آماده سازی: `chore/core-cloud-zero-payment-20261025` بر پایه `codex/dev-core` در Commit `159fe944d20905e61898e8230e126a24f8044f6f`.
- این شاخه تنها پیکربندی توسعه ابری، تست و اصلاح قابلیت حمل C63 را دارد؛ **در main ادغام نشده است**.
- تغییرات UX محلی از جمله «بستن کنترل سناریو» هنوز در کامپیوتر قبلی مانده‌اند و **در این شاخه نیستند**. پس از اتصال دستگاه باید جداگانه بررسی و محافظت شوند.
- C9 و C73، حسابداری، تولید، نیروی انسانی و داده واقعی دست نخورده می مانند.

## روش استفاده
1. وارد GitHub مخزن `sahandgem/mrgem-main-system` شو و این شاخه را انتخاب کن.
2. از Code > Codespaces > Create codespace on this branch استفاده کن. ماشین دو هسته ای و زمان توقف خودکار کوتاه انتخاب کن.
3. اگر سیستم روش پرداخت یا خرید اعتبار خواست، **ادامه نده**.
4. بعد از نصب خودکار وابستگی ها، در Terminal اجرا کن: `npm run dev:core`.
5. در تب Ports حتماً بررسی کن پورت `5174` **Private** است. آن را Public نکن.
6. آدرس خصوصی Forwarded Port را در مرورگر حساب GitHub خودت باز کن و مسیر `/__dev/command-center` را ببین.
7. Codespace را پس از کار Stop کن؛ فضای ذخیره سازی آن حتی در حالت متوقف هم سهمیه مصرف می کند.

## کیفیت و هزینه
- GitHub Actions: گردش کار `Core and workspace CI` فقط روی PR مناسب یا اجرای دستی فعال می شود؛ نه Deploy یا اتصال سرویس واقعی.
- بررسی های الزامی بعد از آماده شدن محیط: `npm test` و `npm run build`. سبز بودن CI تا زمان اجرای واقعی **تأیید نشده است**.
- Codespaces روی حساب های شخصی واجد شرایط سهمیه رایگان محدود دارد. مصرف CPU و فضای ذخیره سازی را در Billing بررسی کن؛ هیچ کارت یا شارژ اضافه لازم نیست و نباید وارد شود.
- همه سرویس ها بسته به کشور و وضعیت حساب ممکن است در دسترس نباشند؛ برای محدودیت حساب راه دورزدن پیشنهاد نمی شود.
- مخزن در زمان آماده سازی عمومی بود. این شاخه را حاوی کلید یا داده شخصی نکن؛ خصوصی کردن مخزن مجوز جدا می خواهد.

## مرز تغییرات
این پیکربندی فقط توسعه و پیش نمایش خصوصیِ **هنگام روشن بودن Codespace** را هدف می گیرد، نه انتشار همیشگی روی اینترنت. هیچ Merge، Deploy، Migration یا اتصال به داده واقعی در این شاخه انجام نمی شود.
